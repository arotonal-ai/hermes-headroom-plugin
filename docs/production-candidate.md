# Headroom production candidate (P1–P4)

This checkout exposes an inert `headroom-composite` ContextEngine plus metadata-only request classification, tool-result lifecycle, and Responses schema-shaping modules. Registration does not select the engine and does not change the provider, model, base URL, retry policy, cache, or output shaping. Shadow request events are appended to the existing bounded local Headroom JSONL event log; they contain counters, byte/character totals, supplied correlation/usage/provider/cache/latency metadata, and no request content, arguments, prompts, secrets, or schema text.

Select the composite engine explicitly with `context.engine: headroom-composite`. Lifecycle and request shaping remain disabled unless their `context_reduction.lifecycle.enabled` or `context_reduction.request_shaping.enabled` fields are explicitly set. Lifecycle supports bounded `hot_tool_results`, `warm_tool_results`, `aggregate_budget_chars`, and `materiality_chars`. It first preserves Hermes's system/head/tail regions, keeps configured hot tool results exact, and uses the existing Headroom reduction path for eligible warm/cold/grouped results. A replacement is accepted only when it includes a real durable CCR marker and passes structure, pairing, and configured materiality checks. Cold results retain bounded critical anchors plus the durable recovery handle. Failure or a non-useful response falls back to Hermes's built-in compressor with the original messages.

Provider-native `defer_loading` shaping is implemented as an explicit compatibility fixture only. The current local Hermes Codex preflight rejects `tool_search` and strips `defer_loading`, so normal configuration fails safe with no request mutation. With `compatibility_test: true`, shaping applies only to supported OpenAI/Codex Responses modes and a sole provider disclosure owner, injects exactly one provider-native `tool_search`, and marks nonresident tool objects. Chat, Anthropic, Bedrock, unknown modes, and multi-owner configurations remain unchanged. Resident candidates include terminal/read/search/mutation tools, `headroom_retrieve`, and `innocent`.

Rollback each layer independently: keep `context.engine: compressor`, leave lifecycle and request shaping disabled, or remove this candidate worktree. The existing `headroom_retrieve` tool remains the sole retrieval schema. Lifecycle keeps no unredacted local source cache and makes no cross-restart recovery claim; recovery durability belongs to CCR markers returned by the configured Headroom service. This candidate is not a live promotion and does not alter any active/global route.
