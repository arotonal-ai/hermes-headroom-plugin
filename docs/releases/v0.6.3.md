# v0.6.3 — portable test and runtime-authority hardening

## Purpose

Publish the verified portability and runtime-authority reconciliation merged through PR 36 without changing provider/model routing or the managed Headroom/LiteLLM pair.

## Changes

- Make `python scripts/run-isolated-unit-tests.py` the canonical test entrypoint and isolate pytest/PyYAML from the production Hermes venv.
- Strip inherited Python and `HEADROOM_*` environment state from unit-test subprocesses.
- Reconcile the public port/service contract: `8787` is the portable default, `28787` is retired, and instance ports such as `28789` remain explicit local overrides.
- Keep the Hermes plugin listener-free and remove the unused legacy service-unit constant from the proxy client.
- Align compatibility documentation with the blocking Python 3.11/3.14 matrix on Linux, macOS, and Windows.
- Expose the temporal in-memory CCR contract: 1,800-second default TTL, no restart survival, and no plugin-local exact fallback.

## Compatibility

- Python: `>=3.11,<3.15`.
- Managed runtime: `headroom-ai[proxy]==0.32.1` with `litellm==1.94.0rc3`.
- Existing-deployment reconciliation remains separate from clean-install support.

## Publication gate

Before publication, require the isolated unit suite, repository readiness audit, multi-OS CI/lifecycle checks, release-candidate gate, wheel/sdist inspection, checksums, clean public installation, and explicit verification that the active owner runtime and provider routing were not changed by release preparation.
