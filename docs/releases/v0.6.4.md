# v0.6.4 — Headroom 0.33 and durable local-alias recovery

## Purpose

Promote the managed owner-local runtime to `headroom-ai[proxy]==0.33.0` while preserving exact fail-open behavior when upstream compression does not provide a durable CCR marker.

## Changes

- Pin the managed runtime and packaged `proxy` extra to `headroom-ai[proxy]==0.33.0` with `litellm==1.94.0rc3`.
- Preserve semantic tool identity when routing eligible Hermes tool results to Headroom 0.33.
- When compression is useful but has no provider marker, synthesize a content-addressed `local_…` recovery alias only if the default-off profile-local exact store accepts the non-sensitive source.
- Keep the exact original result when the local store is disabled, rejects the data class, exceeds quota, or cannot persist the source.
- Expose `marker_origin` in metadata so provider and synthesized-local authority remain distinguishable.

## Safety boundary

The local store remains explicit opt-in, profile-isolated, TTL/quota bounded, content-addressed, checksum verified, and private-permissioned. Secrets, credentials, instructions, final answers, canonical memory, edit/recovery material, and other protected classes remain exact or create only redacted metadata. Provider routing and paid backends are unchanged.

## Admission evidence

- Official PyPI `0.33.0` sdist SHA-256: `97d817e5923903d72bed24f75e0424e9cb7f86b3ddde0fc1acec4f3f85deeb5a`.
- Wrapped lifecycle functions retain the 0.32.1 signatures and ASTs; `load_manifest` adds only upstream deprecated-image migration.
- Isolated dependency/runtime, complete plugin tests, integrated Hermes terminal → deferred Tool Search/Describe/Call → exact retrieval, release-candidate, security, local production E2E, and rollback evidence are required before promotion.

See [`docs/evidence/headroom-033-api-compatibility.json`](../evidence/headroom-033-api-compatibility.json) and [`docs/compatibility.md`](../compatibility.md).

## Portability boundary

Owner-local Linux admission does not substitute for the blocking native Linux/macOS/Windows Python-boundary workflows required before a tagged cross-OS release.
