# v0.6.2 — managed v0.6.0 uninstall compatibility

## Purpose

Patch the live-upgrade path discovered while moving an exact v0.6.0 managed deployment to v0.6.1. The v0.6.1 manager correctly failed closed because the saved v0.6.0 manifest predated the required `HEADROOM_DISABLE_KOMPRESS=1` field, but that also prevented the manager from invoking the old deployment's symmetric upstream remove operation.

## Change

- `uninstall` may accept exactly one historical environment contract: the complete v0.6.0 `base_env`, which differs only by the absence of `HEADROOM_DISABLE_KOMPRESS=1`.
- The manifest must still match profile, port, preset, runtime, supervisor, scope, loopback host, provider mode, proxy arguments, workspace path, empty targets, empty mutations, and empty tool environments.
- Status, setup, reconciliation, extra/missing environment variables, identity drift, provider targets, and mutation history remain fail-closed.

## Validation

- Live reproduction: v0.6.1 uninstall returned `UNINSTALL_BLOCKED` with only `base_env` mismatched and invoked no upstream mutation.
- Safe live recovery: v0.6.0 doctor and uninstall succeeded; v0.6.1 setup on the preserved loopback port returned `RUNTIME_FULL_DURABLE`.
- Regression tests cover the exact accepted v0.6.0 contract, rejection by status, rejection of an extra variable, identity mismatch, and mutation history.
- Full isolated unit suite, repository audit, and blocking CI/lifecycle gates remain required before publication.
